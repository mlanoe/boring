Boring Language

Beta

fixedN_M / ufixedN_M: binary fixed-point scalar types

Status: Phases 1, 2, 4 and 5 implemented in the Rust interpreter, the transpiler (generated newtype, W ∈ {8, 16, 32, 64}, and signed W = 128, see Phasing §4) and the self-hosted interpreter, with a shared test corpus (tests/cases/fixed_point_*.br). Implemented: the core types, Members (raw, fromRaw, epsilon/min/max, floor/ceil/round/trunc/fract/abs/ signum/min/max/clamp), and the overflow-policy and rounding variants wrappingAdd/Sub/Mul/Div, saturating…, checked… (returning T?) and mulRound/divRound. Also implemented, as native methods rather than library code: sqrt, sin, cos, tan, exp, ln (Phase 5 — see below). GPU backends: CUDA, ROCm/HIP and Metal and wgpu (W ≤ 64) are implemented (see GPU backends; CUDA/ROCm verified by codegen tests only, no NVIDIA/AMD hardware was available; Metal and wgpu are also verified on the device, byte for byte against boring run; Metal's 64-bit formats use mulhi plus a shift-subtract division, wgpu's a vec2<u32> limb pair with emulated 128-bit product / division). 128-bit formats (Phase 4) are signed-only. The former open questions are resolved in Decisions. Implementation notes (where the code differs from, or narrows, the text): - Names are reserved by shape: fixedN_M/ufixedN_M always (an invalid one is a parse error), iN_M/uN_M only when valid, so i3_4 as a variable name still works. Declaring a struct/enum/trait/type/use … as with a reserved format name (struct u8_8) is a parse error. - 0.1 as fixed16_16 — a cast of an untyped literal — rounds to nearest like a contextual literal; only casts of computed values truncate. - Strictness against int/float variables is enforced at let bindings and in operators, and in the interpreters at every other binding site too: a non-literal int/float passed to a fixed parameter, constructor field or init parameter, assigned to a fixed variable or field, or returned from a fixed function needs an explicit as. Only an untyped literal adopts the format. The same holds per slot of a tuple literal meeting a (fixedN_M, …) type (argument, let, return). - fixed → fixed / int → fixed / float → fixed casts that do not fit give nil in the interpreters and panic in generated Rust. - The Rust newtype definitions are appended to the generated program for every format that appears in it; a used module's formats are emitted too in the flattened --emit-rust output (tests/emit_rust_modules.rs).

Problem Statement

Boring has integers (int8..int128, uint8..uint128) and IEEE floats (float16/float32/float64), and nothing in between. The newtype type Q as int gives a distinct type but no fixed-point semantics: no shifted * and /, no 1.5 literals, no formatting.

Fixed-point reals are wanted for:

  • The kernel target (Rust-for-Linux, no_std): floating point is not

usable in kernel code, so fixed-point is the only way to have fractional values.

  • Determinism: identical bits on CPU, Metal, wgpu and CUDA. Floats are not

(FMA contraction, float16, no f64 on Metal). Matters for the Whisper / LLM benchmarks and for simulations (game logic, scratch-boring).

  • GPU kernels: MSL / WGSL / CUDA all have native integers, so a fixed-point

value lowers to plain integer operations.

Out of scope here: decimal fixed-point (scale 10⁻ᵈ, for money). That is a separate type family with its own naming; this document is binary only (scale 2⁻ᴹ).

The types

A fixed-point type has two sizes: the number of integer bits N and the number of fractional bits M. N + M is the storage width and must be one of 8, 16, 32, 64, 128.

FormMeaning
fixedN_Msigned; N integer bits including the sign bit, M fractional bits
ufixedN_Munsigned; N integer bits, M fractional bits

The value of a variable whose raw storage is the integer r is r / 2^M. Range of fixedN_M: -2^(N-1) .. 2^(N-1) - 2^-M; resolution 2^-M.

Aliases

Following the existing iX / uX / fX aliases of intX / uintX / floatX:

CanonicalAlias
fixedN_MiN_M
ufixedN_MuN_M

The family is told apart by shape alone: one number → integer (i32) or float (f32); two numbers joined by _ → fixed-point (i16_16).

Common formats (any N + M in the valid widths is accepted):

Constraints:

  • N + M not in {8, 16, 32, 64, 128} → checker error.
  • fixedN_M needs N >= 1 (sign bit). ufixedN_M allows N = 0

(ufixed0_16: values in [0, 1)). M = 0 is legal but degenerate (identical to the integer type); the checker accepts it with no warning.

  • The names fixedN_M, ufixedN_M, iN_M, uN_M (with valid N, M) are

reserved type names, exactly as i32 is today.

  • There is no fixed / real bare alias to a default format. A bare name

would hide the precision, which is the whole point of the type.

Why not real…: real32 (float) and real16_16 (fixed) would both be 32 bits yet behave very differently (NaN/inf and relative precision vs. exact absolute resolution and overflow). float already carries that distinction.

Literals

Float literals are already contextual (let float32 a = 1.0; a + 3.14 resolves 3.14 to float32). The same rule applies:

boring
let fixed16_16 x = 1.5
let y = x + 0.25            # 0.25 resolves to fixed16_16
let ufixed8_8 z = 200.5     # ok
let fixed8_8 w = 200.5      # ERROR — out of range [-128, 127.99609375]
  • A float literal not exactly representable is rounded to nearest (ties

away from zero) at compile time. No warning is emitted for an inexact literal (0.1 in fixed16_16): it would fire on nearly every literal.

  • Out-of-range literals are a compile error, same as 300 as uint8.
  • An integer literal (3) also resolves to the fixed type from context

(let fixed16_16 n = 3).

  • Digit separators work as everywhere (0.000_015).

Mixing and casts

Same strict rule as fixed-width integers and floats: two different fixed-point formats never mix implicitly, nor do fixed-point and int/float.

boring
let fixed16_16 a = 1.5
let fixed8_24  b = 0.5
let c = a + b                     # ERROR — cannot mix fixed16_16 and fixed8_24
let c = a + (b as fixed16_16)     # OK
let d = a * 2                     # OK — `2` is an untyped literal
let n = 3
let e = a * n                     # ERROR — int and fixed16_16 do not mix; cast
let e = a * (n as fixed16_16)     # OK

as conversions (all runtime conversions truncate toward zero; only literals round to nearest, since they are a decimal value the author wrote rather than a computation):

From → toBehaviour
fixed → fixed (other format)shift by the difference of M; narrowing the integer part is range-checked, nil / error if it doesn't fit (same as integer narrowing); dropping fractional bits truncates toward zero
int → fixedexact, range-checked
fixed → inttruncates toward zero
float → fixedtruncates toward zero (like Rust's as), range-checked; NaN/inf → out of range
fixed → floatnearest representable float (exact whenever the float mantissa is wide enough)
fixed → stringvia interpolation only, as everywhere (no string(x))

Arithmetic semantics

For fixedN_M stored in intW (W = N + M), with raw values ra, rb:

OpDefinitionResult type
a + b, a - bra ± rbsame format
-a-ra (signed only)same format
a * b(ra * rb) >> M, computed in a 2W-bit intermediatesame format
a / b(ra << M) / rb, computed in a 2W-bit intermediatesame format
a % bra % rbsame format
a < b, ==, …ra < rbbool
<<, >>, &, |, ^not defined on fixed-point (use .raw)
  • Result is never widened: fixed16_16 * fixed16_16 is fixed16_16.

Callers who want headroom cast first.

  • Rounding of * and /: truncate toward zero, consistent with integer

/ and with fixed → int, and symmetric ((-a) * b == -(a * b)). An arithmetic shift (floor) is cheaper but asymmetric; round-to-nearest is more accurate (see mulRound/divRound in Phasing).

  • Overflow follows the integer policy: panic in debug, wrap in release.

Explicit variants, mirroring whatever the integer types expose: a.wrappingMul(b), a.saturatingMul(b), a.checkedMul(b) (→ T?).

  • Division by zero: panic, as for integers.
  • The 2W-bit intermediate for W = 128 (fixed64_64, …) does not exist

natively; it is emulated by src/fixed_wide_core.rs. See Phasing §4 (signed only, at most 126 fractional bits, no math functions).

Formatting

  • "{x}" prints the exact value as a decimal with trailing zeros trimmed.

This is always finite (denominator is a power of two): fixed16_16 of 1.5 prints 1.5, of raw 1 prints 0.0000152587890625.

  • "{x:.3f}" rounds to nearest to 3 places, same spec as floats.

Rust mapping (transpiler)

Generated newtype, no external dependency (works in no_std and in the Linux kernel target). Emitted once per format actually used, into the generated project's prelude module:

rust
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Default)]
#[repr(transparent)]
pub struct Fixed16_16(pub i32);

impl Fixed16_16 {
    pub const FRAC_BITS: u32 = 16;
    pub const EPSILON: Self = Self(1);
    pub const fn from_raw(r: i32) -> Self { Self(r) }
    pub const fn raw(self) -> i32 { self.0 }
}

impl core::ops::Add for Fixed16_16 { type Output = Self; fn add(self, o: Self) -> Self { Self(self.0 + o.0) } }
impl core::ops::Mul for Fixed16_16 {
    type Output = Self;
    fn mul(self, o: Self) -> Self { Self(((self.0 as i64 * o.0 as i64) / (1i64 << 16)) as i32) }
}
// Sub, Neg, Div, Rem, the *Assign variants, Display, Debug, …

i64 / (1 << 16) truncates toward zero, matching the stated semantics (an arithmetic >> would floor). Overflow checks go through the same debug_assert/wrapping_* policy the transpiler already uses for integers.

Formats are emitted by a small generator keyed on (signed, N, M), not hand-written per format. Literals are folded to their raw integer at transpile time (1.5 in fixed16_16 → Fixed16_16(98304)).

Interpreter (boring run) and self-hosted interpreter

New runtime variant Value::Fixed { raw: i128, signed, n, m } with a matching Type::Fixed { signed, n, m }. The interpreter implements exactly the semantics table above using i128 math (hence no 2W-bit problem for any format ≤ 64 bits). This is the reference semantics; the transpiled Rust, the self-hosted interpreter (boring/interpreter/) and GPU lowerings must agree with it, and the shared test-case corpus (tests/cases/*.br + .expected) gets fixed-point cases so all four builds are checked against one answer.

Metal (implemented, W ≤ 64)

src/transpiler/metal/device.rs (kernel code) and metal/host.rs (host). Same rules as CUDA above, with MSL types: fixedN_M fields, buffers, parameters and locals are char/short/int (uchar/ushort/uint for ufixed); * is (int)(((int64_t)a * (int64_t)b) / (int64_t)2^M) and / is (int)(((int64_t)a * (int64_t)2^M) / (int64_t)b) (uint64_t for unsigned formats), both truncating toward zero. Untyped literals fold to the raw constant (also in function arguments and return position); as casts between fixed/int/float and other fixed formats, .raw, fromRaw, epsilon/min/max, floor, ceil, trunc, fract, abs, min and max are lowered. On the host the generated FixedN_M newtype is repr(transparent), so a Vec<FixedN_M> is bit-identical to the device buffer, and literals/casts fold as in the general pass.

  • 64-bit formats (fixed32_32, fixed48_16, ufixed32_32, …; raw is long/ulong):

+ - %, comparisons, floor/ceil/trunc/fract/abs/min/max, as casts, .raw, fromRaw, epsilon/min/max are the same integer ops (literals above the i32 range get l/ul suffixes; the signed min is spelled -9223372036854775807l - 1l). * and / call helpers emitted once into the MSL header, only when a 64-bit format is used: they work on the magnitudes (so the quotient truncates toward zero, never a shift), * takes the 128-bit product from a * b and mulhi(a, b) and shifts it right by M, / is a 64 + M-step shift-subtract division of a << M by b; the final raw keeps the low 64 bits (wraps). The division is slow (a loop per /), the multiply is cheap. fixed -> float and float -> fixed go through the device float32 (24-bit mantissa), so large 64-bit raws round; use integer casts for exactness.

  • Compile errors on Metal, never a silent narrowing: 128-bit formats and the degenerate

ufixed0_64 (M = 64, whose scale 2^64 has no 64-bit constant), sqrt/sin/cos/tan/exp/ln, round, signum, clamp, wrapping*/saturating*/checked*, mulRound/divRound.

  • Overflow wraps and division by zero is undefined, as for any GPU integer op. fixed -> float

goes through the device float (float32), so a 32-bit raw above 2^24 may round.

  • Verified on an Apple GPU: tests/metal_codegen.rs::fixed_point_kernel_runs_on_metal_and_matches_interpreter

runs examples/fixed_point_kernel.br (fixed16_16, fixed8_8, fixed8_24, ufixed16_16, members, helper functions) on the device and compares with boring run byte for byte. The 64-bit formats are verified the same way (fixed_point_64_kernel_runs_on_metal_and_matches_interpreter, examples/fixed_point_kernel64.br: fixed32_32, fixed48_16, ufixed32_32, negative operands, carries across the 32-bit halves) plus fixed_point_64_mul_div_edge_sweep_matches_exact_math_on_metal: * and / of fixed32_32, fixed48_16, fixed1_63 and their unsigned twins over 288 edge raw pairs (around 2^32, 2^62, 2^63-1, both signs, top-bit-set raws) equal exact 128-bit arithmetic on the Apple GPU, including wrapped results (the interpreter reports overflow instead of wrapping, so overflowing cases are checked against exact math, not boring run).

wgpu (implemented, W ≤ 64)

src/transpiler/wgpu/device/fixed.rs (kernel code), wgpu/host.rs + wgpu/mod.rs (host). Same rules as CUDA/Metal, lowered to WGSL's only integer scalars: a fixed-point value is an i32 (ufixed: u32) holding the raw integer. An 8/16-bit raw lives sign-/zero-extended in that register and is re-narrowed after every operation that can leave its range (extractBits(x, 0u, W)), so + - % wrap like the narrow type.

The bp_fx_* helpers are module-level WGSL functions emitted once, only when a kernel uses them (a program with + - %, compares and W ≤ 16 operations carries none). A scalar let fixed16_16 k kernel field is uploaded as its raw i32/u32 in the params struct (a 64-bit one as two u32 slots k_lo / k_hi, a [T, N]'const array of 64-bit raws as 2N u32 words read back as limb pairs, the host struct staying free of padding). On the host, buffers are Vec<FixedN_M> — the generated repr(transparent) newtype, marked bytemuck::Pod, so it is bit-identical to the device buffer and needs no conversion (the shared kernel-host emitters' x as <fixed> casts are dropped).

  • Compile errors on wgpu, never a silent narrowing: 128-bit formats — as a kernel field, parameter, return type or in an operation; a fixed-point 'actor buffer

(WGSL atomics are 32-bit i32/u32 only); sqrt/sin/cos/tan/exp/ln, round, signum, clamp, wrapping*/saturating*/checked*, mulRound/divRound; a literal out of range.

  • Overflow wraps and division by zero is undefined, as for any GPU integer op. .raw is a 32-bit int on this

target, so the raw of a ufixed with W = 32 above 2^31 wraps and the raw of a 64-bit format is its low 32 bits (read the full raw back by copying the buffer to the host, where .raw is 64-bit); fixed -> float goes through f32, so a raw above 2^24 may round, and float -> fixed (64-bit too) is exact only to f32's 24-bit mantissa. int fields are i32 on wgpu, so integer buffers fed to / read from a 64-bit kernel must fit 32 bits.

  • A 64-bit * / / costs one 128-bit multiply / up to 126 shift-subtract steps per element: correct but slower

than Metal/CUDA's native 64-bit path; prefer a ≤ 32-bit format when the range allows.

  • Verified on a real GPU (wgpu over Metal on Apple silicon):

tests/wgpu_codegen.rs::fixed_point_kernel_runs_on_wgpu_and_matches_interpreter runs examples/fixed_point_kernel.br and fixed_point_edge_values_run_on_wgpu_and_match_interpreter sweeps * / %, floor/ceil/trunc/fract/min/max, casts and -/abs on mixed signs and magnitudes for fixed16_16, fixed8_24, ufixed16_16, ufixed0_32, fixed8_8, ufixed8_8 and fixed4_4, both compared with boring run byte for byte.   • buf[i].min(x) / buf[i].max(x) on a fixed-point element of a kernel array is the plain member (the

extremum; the buffer is untouched) in boring run and on every GPU target. (For integer elements the same spelling is the atomic read-modify-write form.)

Checker / grammar changes

  • spec/grammar.bnf: extend numeric_type with

("fixed" | "ufixed") INT "_" INT and the aliases

("i" | "u") INT "_" INT. They are plain identifiers to the lexer; the checker recognises the shape (a digits-underscore-digits suffix after a reserved prefix), so no lexer change is needed — and no . in a type name (real16.16 would collide with t.0 tuple access and a as T.16).

  • Scalar rules apply: mut on a fixed-point is an error (use var), no

generic arguments, < after as fixedN_M is always an operator.

  • type Alias as fixed16_16 newtypes work like any numeric newtype

(Copy derived).

Phasing

  1. Core: parser/checker names + validity rules, literals, strict mixing,

as casts, + - * / % and comparisons, formatting, interpreter, Rust newtype for W ∈ {8, 16, 32, 64}, tests in the shared corpus. 2. Members: floor/ceil/round/fract/abs/min/max/clamp, wrapping*/ saturating*/checked*, and mulRound/divRound (round to nearest). 3. GPU: CUDA first, then Metal, then wgpu (with the limb emulation) — all done for W ≤ 32, and for W = 64 on every backend. 4. 128-bit formats (fixed64_64, fixed32_96, fixed128_0, …). Implemented for signed formats with at most 126 fractional bits. - src/fixed_wide_core.rs (dual-use like fixed_math_core.rs: compiled into the Rust interpreter, pasted as mod __fxw into generated programs; ported line for line to fxw_* in boring/interpreter/fixedpoint.br) provides the 256-bit intermediates: 128×128 → 256 product then >> M, and

(|a| << M) / |b| as 256/128-bit long division, both truncating toward zero (or rounding to nearest for mulRound/divRound). Every helper returns (magnitude, negative, overflowed); when overflowed the magnitude is the low 128 bits, which is what wrapping* needs, while checked*/saturating*/plain operators treat it as overflow. The same helpers serve all widths. Literals (num · 2^M / 10^k) and the exact/{:.Nf} formatting (frac · 10 overflows u128 for large M) also go through them. Unit tests compare the helpers with Python big-integer reference vectors (src/fixed_wide_vectors.rs). - Unsigned 128-bit formats (ufixedN_M, N + M = 128) are rejected with a clear error: the raw value is stored in an i128 / int128 in both interpreters (Value::Fixed, Value.Fixed), which cannot hold a raw value above 2¹²⁷, and the 256-bit helpers work on i128 operands. - At most 126 fractional bits (fixed1_127 is rejected): keeps 2^M an in-range positive i128, which the rounding members and conversions rely on. - sqrt/sin/cos/tan/exp/ln are not supported for 128-bit formats: the 60-bit-internal-precision core computes raw << (60 - M) (and 120-bit products) on an i128, which overflows. They are a runtime error (… is not supported for 128-bit fixed-point formats) in all three implementations. - Not covered: GPU backends (still a compile error for W = 128). - Corpus case: tests/cases/fixed_point_wide.br. 5. Math functions (sqrt, sin/cos/tan, ln/exp). Implemented as native methods, not as Boring library code — the original plan (write them in Boring, out of the compiler) is not possible today: arithmetic on a generic T does not compile, and ext fixed16_16: is rejected, so one Boring definition cannot serve every fixedN_M. They are integer-only (no floats, bit-for-bit identical in all three implementations): src/fixed_math_core.rs (pasted into generated programs and compiled into the Rust interpreter) and a line-for-line port in boring/interpreter/fixedpoint.br; tests/cases/fixed_point_math.br keeps them in agreement. Internal precision is 60 fractional bits (CORDIC for sin/cos, Taylor for exp, an atanh series for ln), results are rounded to nearest to the format's M bits, i.e. accurate to about 2 ulp of the format and no better than ~2⁻⁵⁴ whatever the format. sqrt is the exact floor. A negative sqrt, a non-positive ln, a tan where cos is zero and any result outside the format's range are errors.

Decisions

Questions raised while drafting, and how they were resolved:

  1. Rounding of * / /: truncate toward zero. Round-to-nearest is

available as mulRound/divRound (Phase 2); the default is unchanged. 2. Inexact literals (0.1): rounded to nearest, no warning. Only an out-of-range literal is an error. 3. fixed mixed with int: an error in the first cut (cast explicitly); only untyped literals are exempt. Possible later extension: allow fixed * int, int * fixed, fixed / int as exact scaling, if the cast proves too noisy in practice (then +, - and comparisons with int must be decided too). 4. Narrowing casts: bare as is allowed and every runtime conversion truncates toward zero (consistent with float → int); only literals round to nearest. 5. fixed crate backend: dropped. The generated newtype is the only backend; revisit only if Phase 5's math functions show a real need.
